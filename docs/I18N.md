# Languages (EN / DE / FR / IT)

The club is Swiss. A junior opens this app on a phone and it should be in their language —
not half in their language, which is worse than all English because it reads like a bug.

## The policy

**UI chrome is translated. Tactical content is not.**

Translated: navigation, buttons, table headers, empty states, form labels, error messages,
toasts, the Basics rules explainer, and every sentence the app writes about the player's own
data ("Your first session each week targets endurance").

Not translated, on purpose:

| What | Why |
| --- | --- |
| Play names and the coach's notes on a play | The coach typed them. Translating a coach is not our job. |
| `ZONE_HINTS` in `js/film.js` — the coaching hint attached to each goal-mouth zone | Coaching content. Open question: a German hint would serve a Swiss junior better. Ask before changing. |
| `js/help.js` — the whole "how to use" guide | ~245 lines of dense prose, still English. The largest remaining gap. |
| Brand and proper names | Triibholz, THPLAY, Spond, wpmatch.ch, Swiss Aquatics, World Aquatics, Garmin, YouTube |
| Technical tokens | GK, RPE, CSV, ICS, `m:ss`, `docker compose up -d analysis` |

## Adding a string

```js
// js/app.js — the helper is module-scope
T('ui.nextNinetyDays', { n: items.length })

// js/film.js — the helper is called TX, because `T` is already three local variables here
TX('film.noMatchesYet')
```

Then add the key to **all four** language blocks in `js/i18n.js`. `t()` does one thing:
look the key up, fall back to English, replace every `{name}` with `vars.name`. No plurals,
no gender, no ICU. If English needs "1 play / 2 plays", that is two keys.

Values may contain HTML — they are injected with `innerHTML`, so `<strong>` survives and is
often needed to keep the emphasis the sentence was built around.

### Rules that are not obvious

- **Never split a sentence across two keys.** German and French reorder; a prefix key plus a
  suffix key can only ever come out broken. Widen the key to the whole sentence and put a
  `{placeholder}` where the value goes.
- **Label tables must be functions, not consts.** A module-level `const FOCUS_LIST = [...]`
  freezes whatever language the app booted in. This bit us once already.
- **Watch the quoting.** `'<div class="muted">No plays</div>'` is a single-quoted string —
  `T('x')` inside it breaks the quoting. Convert to a template literal first.

## The guard — `tests/i18n-scan.mjs`

A source scan, not a DOM diff: it points at the exact line, and it catches a string the day it
is written rather than whenever some test happens to render that view. `tests/smoke.mjs` runs
it as a **ratchet** — `BASELINE` may only ever go down, so the next hard-coded string fails
the build.

It reads three things:

1. copy inside template literals, however deeply nested, including copy that sits outside any
   tag;
2. copy inside ordinary quotes that contains markup (`cond ? '<span>no clip</span>' : ''`);
3. `toast(...)` calls.

Plus two parity checks on the dictionary itself, because this is how a translation actually
breaks in front of a user:

- every language defines exactly the same keys;
- every translated value keeps the same `{placeholders}` **and** the same HTML tags as its
  English source. A dropped `{n}` shows the user a literal `{n}`; an unclosed `<strong>` eats
  the rest of the sentence.

### Known limit

A template literal with **no markup at all** — `` `${n} plays left` `` — is not scanned. At
that point it is indistinguishable from the hundreds of code strings that build URLs, class
names and storage keys, and guessing produces false positives that train people to ignore the
guard. Anything with a tag in it is fair game.

### It has lied before

The scanner under-reported for two tranches. Worth knowing, because every one of these fails
*silently* — the count just looks better than it is:

- The template matcher was a regex, so it ended the outer literal at the first backtick inside
  `${...}`. Everything in a nested `map()` template was invisible.
- Copy before the first `<` was skipped: the "text between tags" pattern needs an opening `>`.
- **A quote inside a regex.** `escapeHtml` is built on `/[&<>"']/g`; the walker read that `"`
  as the start of a string and swallowed the next few hundred lines. The whole Dashboard sat
  in that hole. The string-skipper now gives the character back when it hits a newline (a JS
  string cannot contain one), so a bad guess costs nothing instead of hiding a screen.

If you change this file, prove it still works by injecting a string into each of the three
kinds of place and checking all three are reported. A guard nobody has tried to fool is not a
guard.
